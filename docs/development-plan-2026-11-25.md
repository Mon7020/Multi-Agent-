# 智能客服项目开发修改计划

制定于 2026-11-25。初始基线为本地独立仓库 `test2langchain` 的 `master@aca0d76` 加制定计划时的未提交改动。

**交付目标**是让管理员发布一个知识库版本后，用户能通过前台默认的流式聊天获得权限范围内、带可核对出处的回答。Worker 中断、索引构建失败和用户并发连接都要有可验证的处理结果。

## 基线与排期

### 实施进度

- `e00b413` 已加入 WebSocket 连接隔离、未知来源过滤、共享 RAG 参数及对应回归。第 1 至 5 项的完成状态仍以表中的验收条件为准。
- 第 4 项已将 RQ 入队、任务列表和幂等键的写入合并为一次 Redis 事务。同一个键在排队和运行期间复用任务，任务结束后允许再次提交。管理端重试旧任务时，若同键已有活动任务，返回 HTTP 409 并指出活动任务 ID。
- 已用临时 Redis 验证 8 个独立客户端同时提交两个显式文档版本，每个版本各产生一个任务。全库重建目前仍按单个活动任务去重。下一步验证 Worker 在领取后中断的恢复，再结合第 6 项把全库重建绑定到可回滚的索引版本。

最近一次隔离复核选跑了 169 项后端测试，168 项通过，1 项因未知来源文档触发权限过滤异常而失败。临时 Redis 实测确认跨进程任务可以完成，同时暴露了空队列异常、任务领取后中断无法接管，以及已完成任务阻挡后续重建的问题。两个进程读到的 `top_k` 分别为 12 和 10。现有评测有 50 条常规、100 条上下文和 20 条 RAGAS 样本，默认 chat 模式调用普通服务方法。上述数字是改造前记录。

按 **1 名开发者、两个各 10 个工作日的迭代**估算，每个迭代安排 8 人日开发与验证，留 2 人日处理依赖兼容和联调。工时为初估，第一轮干净安装和 Worker 实验后更新。

## 验收场景

1. 建立两份测试文档，一份公开，一份仅运营可见。普通用户在前台提问，得到公开文档的答案和出处。运营用户能在相同条件下引用获准文档。
2. 将公开文档中的一个可核对事实从 A 改为 B，发起重建并中断 Worker。确认任务最终有明确状态，用户在构建期间仍可查询当前已发布版本。
3. 重建成功后，普通用户通过 SSE 提问，回答和出处都指向 B 所在版本。撤销权限后重复同一问题，确认缓存不再返回该文档。恢复授权并回滚索引，验证回答重新引用 A。
4. 用两条用户连接并发提问并断开其中一条。核对回复归属、剩余连接可用性，以及请求、模型调用、检索版本与任务记录能否关联。

## 回归命令

在候选版本的隔离环境中执行，使用临时认证库和专用 Redis。固定响应的测试使用测试替身，真实模型抽样另行记录。以下命令均从仓库根目录运行。

```powershell
python -m pytest -q tests/admin/test_p0_rag_security_trace.py tests/admin/test_knowledge_visibility.py
python -m pytest -q tests/admin/test_task_queue_service.py tests/admin/test_knowledge_async_tasks.py tests/admin/test_knowledge_base_reload_api.py
python -m pytest -q tests/admin tests/test_agent_evaluator.py tests/test_knowledge_chunking_strategies.py tests/test_memory_admin_localization.py
npm --prefix frontend ci
npm --prefix frontend run test:admin
npm --prefix frontend run build
```

第 4、6、7 项各自补上对应的进程中断、索引发布和 SSE 契约回归，并接入第 9 项发布演练。真实模型质量由抽样评测报告说明，单元测试通过数用于衡量软件回归。
